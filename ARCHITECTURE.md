# K-13 architecture

A bot for https://scrabblebot.spacetimedb.com (database `scrabblebot` on
https://maincloud.spacetimedb.com). Its edge is memory: it mines every public
match ever played, profiles every opponent, and bids against what it knows
about the bots actually seated with it. `README.md` gives the overview
(pipeline, training, results, how to run); this file covers the layout and
the rule facts the code relies on.

The game server's source is https://github.com/clockworklabs/scrabblebot
(`spacetimedb/src/game.ts`, `index.ts`, `schema.ts`, `letters.ts`,
`dictionary.ts`, `lobby.ts`, `tournament.ts`). Treat it as the source of truth
for rules; where the upstream bot guide (`docs/bot-guide.md` there) disagrees
with the code, the code wins (see "Rule facts"). Tools that need a checkout
(`npm run generate`, the rehearsal kit, one dictionary test) look for it at
`$K13_UPSTREAM`, default `../scrabblebot/spacetimedb`.

Runtime: Node 22, TypeScript ESM run with `tsx`, no build step needed.
Persistence: built-in `node:sqlite` (`DatabaseSync`), no native deps.
Local imports use the `.js` suffix (`import { x } from "./rules.js"`).

## Layout and ownership

| Path | What |
|---|---|
| `src/core/rules.ts` | Constants and scoring, identical to the server. Shared contract — don't change semantics. |
| `src/core/types.ts` | `MatchView`, `Agent`, `PublicEvent`. Shared contract — extend only by adding optional fields. |
| `src/core/words.ts` | Fast word engine for our own decisions. |
| `src/sim/` | Faithful offline match simulator + baseline agents + parallel runner. |
| `src/memory/` | History miner (anonymous subscription → SQLite) and opponent profiles. |

| `src/agents/` | The official starter strategy as an `Agent` (baseline and fallback). |
| `src/bot.ts`, `src/live/` | Live bot process: connection, credentials, two-stage bidding, tournaments, watchdog, logging. |
| `src/backend/`, `backend/` | K-13's own SpacetimeDB module and its Node client (mirror, derived data, telemetry). See `backend/README.md`. |
| `src/monitor/` | Status reporting. |
| `src/module_bindings/` | Generated by `spacetime generate` from the upstream game module. Don't edit. |
| `src/backend_bindings/` | Generated from `backend/`. Don't edit. |
| `scripts/` | `k13.sh` (tmux runner) and `rehearse/run.ts` (full local tournament rehearsal). |
| `deploy/` | systemd unit templates (bot, miner, local SpacetimeDB). |
| `data/wordlist.txt` | The server's exact dictionary (172,820 words, uppercase). |

| `data/clones.json`, `data/field.json` | Fitted opponent clones and recent real table compositions for the simulator. |
| `logs/` | Live decision logs, JSONL (gitignored). |

## Rule facts (verified in the server code)

- 6 seats; empty seats get server-run simulated bots. Each bot starts with
  100 coins and 5 hidden tiles dealt from the 98-tile bag, so a full match has
  98 - 30 = 68 auctions, one letter each, 1000 ms each.
- Sealed bids; `submit_bid` may be called again before the close and the
  server keeps only the latest bid. A bid above your balance is rejected.
- Vickrey (default): winner pays the runner-up's bid; a lone bidder pays 1.
  Equal top bids are broken randomly (shuffle then stable sort). Bids of 0
  don't count.
- A tile nobody bids on is discarded, not returned to the bag (the upstream
  bot guide says otherwise; the code wins).
- Word reward = floor(sum(letter values) x multiplier): 1x for len <= 3, 1.5x
  at 4, 2x at 5, 2.5x at 6, 3x at 7+. Reward adds to both balance and score.
  Words: 2+ letters, must be in `data/wordlist.txt`, letters from your rack.
- The match ends the instant the last auction closes (bag empty). Live bots
  can't play after that; tiles left on the rack are worth nothing. Simulated
  bots play inside the closing transaction, so they can use the last tile.
- Simulated bots bid `clamp(base + U{-2..2}, 1, balance)` where base is
  value-1 (Cheapskate), value (ValueBidder), value+2 / vowels value+4
  (Aggressive). Right after winning a tile they play the server's
  `findBestPlayable(rack, 3)`: longest first, then alphabetical.
- Ratings: OpenSkill on finishing order, shown Elo-scaled, start 1500.
  Finishing place matters, not raw score.

## Data rules

- Public tables are fair game, including `auction_top_bid_archive`: the
  server publishes finished matches' winning bids on purpose ("bots can't act
  on the info, so it's safe to expose").
- Never read `visible_auction_top_bids`: it shows live winning bids to
  spectators and hides them from bots. Using it from any identity breaks the
  game's rules. Nothing in this repo subscribes to it, ever: subscribe to
  named tables, never `subscribeToAllTables()` from a non-bot identity.
- One bot, one process. No second bot, no collusion.

## Live constraints

- Round trip to maincloud is ~90 ms from the deployment host. A bid must arrive
  before `closes_at`; leave a safety margin of at least 150 ms.
- The live bot must never crash on a refused reducer call; log and continue.
- Tokens live in `.token-<BOT_NAME>` (gitignored). Never print a token.
